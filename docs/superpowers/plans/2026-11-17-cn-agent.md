# CN Agent (warden-cn-agent v1.6.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 国内机运行常驻 Go agent（内置 DNS 收编 dnsmasq+watchdog），与网关通过 10 秒心跳完成"上报状态 + 领命令 + 拿最新分流域名"，面板在线管理域名与机器。

**Architecture:** 两个新二进制角色共用一个 module：`cmd/warden-cn-agent`（国内机，复用 `internal/dnsproxy` 并为其加降级模式）+ 网关侧 `internal/panel/cnagent.go`（注册表持久化到 DataDir + `/api/agent/*` 与 `/api/cnmachines*` 端点）。分发走网关自己的 GitHub 代理短路径直取 GitHub Releases，网关不托管二进制。bootstrap.sh `cn-setup` 增加 agent 模式（`--enroll-token`），迁移顺序按 spec §9.4。

**Tech Stack:** Go 1.x（module `github.com/tktogether/warden-gateway`）、`github.com/miekg/dns`（已有）、systemd（`Restart=always` + `WatchdogSec` + sd_notify）、bash（bootstrap.sh）。

**Spec:** `docs/superpowers/specs/2026-11-17-cn-agent-design.md`（计划与 spec 冲突时以 spec 为准；spec §8.2 数据安全、§9.4 迁移顺序是验收标准）。

## Global Constraints

- 心跳默认 **10 秒 ±20% 抖动**；网关 30 秒无心跳判离线；同 token 心跳间隔 < 8 秒返回 429。
- token 与 enroll token 只存 SHA-256（`config.HashAccessKey`），enroll token 一次性、15 分钟过期。
- agent 永不黑洞 DNS：降级 = 分流域名转上游直连（`SetDegraded(true)`），上游失败返回 SERVFAIL（现状即可）。
- probe 分类值固定为：`OK` / `LINK_443_BLOCKED` / `LINK_PORTS_BLOCKED` / `C_DOWN` / `LOCAL_BROKEN`。
- 所有落盘：网关侧 0600；agent 侧 `agent.json` 0600、`state.json` 0644。
- agent 端点无 CSRF/session，认证仅 Bearer token；面板端点全部走 `s.guard`。
- 每 task 完成跑 `go test ./...`（shell 任务加 `bash -n bootstrap.sh && bash toolbox.sh self-test`）；提交信息用英文祈使句。
- 全程不引入新第三方依赖（只用标准库 + 已有 `miekg/dns`）。

## Review Focus

1. **网关升级丢注册表** → 注册表落盘 Task 9 的测试覆盖"重启后机器还在"。
2. **agent 崩溃 = 全机 DNS 断** → resolv.conf 双 nameserver 由 bootstrap 落地（Task 14）；单测只能锁 agent 侧 `Serve` 失败时状态上报 error（Task 6），resolv.conf 正确性在 Task 14 用 grep 断言锁两行 nameserver。
3. **降级误判（本机断网当网关故障）** → probe 的对照组先行，Task 3 测试锁定 LOCAL_BROKEN 优先于一切网关故障分类。
4. **心跳被 429/401 后 agent 自毁** → Task 6 测试锁定：非 200 响应不产生任何本地动作，仅记录。
5. **自升级坏包替换运行中二进制** → Task 7 测试锁定 sha256 不匹配时原二进制不变、无 .new 残留。
